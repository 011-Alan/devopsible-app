PART 1 — Creating Logfiles and Appending Data Automatically
1. Create a logfile and append data repeatedly

Suppose you want to maintain a file called activity.log and keep adding entries whenever something happens.

Method 1: Append a line manually
echo "Script executed successfully" >> activity.log

The >> operator appends data to the end of the file.

Compare:

Operator	Behaviour
>	Creates a file or overwrites its existing contents
>>	Creates a file if necessary, then appends to it
<	Reads input from a file
2>	Redirects error output to a file
2>>	Appends error output to a file
&>	Redirects standard output and standard error to a file in Bash
2>&1	Redirects standard error to wherever standard output currently goes

Remember: If you want to preserve previous entries, use >>, not >.

Method 2: Automatically add timestamps

Suppose you want every entry to contain the date and time.

echo "$(date '+%Y-%m-%d %H:%M:%S') - Script executed" >> activity.log

Example output:

2026-10-27 08:30:15 - Script executed
2026-10-27 08:31:20 - Script executed
2026-10-27 08:35:42 - Script executed

Each execution appends a new entry.

Method 3: Create a reusable logging function

Instead of repeatedly writing the timestamp command, define a function.

Create logger.sh:

#!/bin/bash

LOGFILE="activity.log"

log() {
    echo "$(date '+%Y-%m-%d %H:%M:%S') - $*" >> "$LOGFILE"
}

log "Program started"
log "Reading configuration"
log "Processing data"
log "Program completed"

Run it:

bash logger.sh

Your logfile will contain:

2026-10-27 08:30:15 - Program started
2026-10-27 08:30:15 - Reading configuration
2026-10-27 08:30:15 - Processing data
2026-10-27 08:30:15 - Program completed

The function log() accepts a message and appends it to the logfile.

Notice the use of "$*" and "$LOGFILE".

Quoting variables helps prevent problems with spaces and shell word splitting.

A slightly more robust version:

#!/bin/bash

LOGFILE="activity.log"

log() {
    printf '[%s] %s\n' \
        "$(date '+%Y-%m-%d %H:%M:%S')" "$*" >> "$LOGFILE"
}

log "Application started"
log "User logged in"
log "Application terminated"

Using printf gives you more predictable formatting than echo.

2. Log successful and failed commands

Suppose you are running a backup script and want to record whether the backup succeeded.

#!/bin/bash

LOGFILE="backup.log"

if tar -czf backup.tar.gz project/; then
    echo "$(date '+%F %T') - Backup successful" >> "$LOGFILE"
else
    echo "$(date '+%F %T') - Backup failed" >> "$LOGFILE"
fi

Here, if evaluates the exit status of tar.

Exit status 0 means success.
A nonzero exit status indicates failure.

This is better than simply logging that a command was executed: you are recording its result.

Capture both output and errors in a logfile
#!/bin/bash

LOGFILE="script.log"

python3 process.py >> "$LOGFILE" 2>&1

This appends both normal output and error messages to the logfile.

If you want to record when the operation starts and finishes:

#!/bin/bash

LOGFILE="script.log"

echo "[$(date '+%F %T')] Started" >> "$LOGFILE"

if python3 process.py >> "$LOGFILE" 2>&1; then
    echo "[$(date '+%F %T')] SUCCESS" >> "$LOGFILE"
else
    status=$?
    echo "[$(date '+%F %T')] FAILED with exit code $status" >> "$LOGFILE"
fi

Important: $? contains the exit status of the most recently executed command. That's why we save it immediately inside else.

3. Append log entries automatically at regular intervals

Suppose you want to record the current date and time every minute.

#!/bin/bash

while true; do
    echo "$(date '+%F %T') - System check performed" >> system.log
    sleep 60
done

Run:

bash monitor.sh

It will append a line every 60 seconds until you stop it with Ctrl+C.

This is a basic monitoring loop.

Better approach: Use cron for scheduled scripts

If you want a script to run every five minutes, you can schedule it instead of keeping an infinite loop running.

Open your user's crontab:

crontab -e

Add:

*/5 * * * * /home/alan/check_system.sh >> /home/alan/system.log 2>&1

This runs the script every five minutes and appends its output and errors to the logfile.

Use absolute paths in cron jobs because cron may start with a different working directory and a smaller environment than your interactive shell.

To list your scheduled jobs:

crontab -l

To remove a scheduled job, edit the crontab and delete its entry.

Note: Cron is suitable for scheduled execution. If you need a continuously running service, consider a systemd service and timer instead. WSL environments may require additional configuration for services and cron to run as expected.

4. Log every command executed by a Bash script

At the top of a script, you can use:

#!/bin/bash

set -x

echo "Starting"
mkdir -p output
touch output/result.txt

set +x

echo "Finished"

set -x prints commands as Bash executes them.

This is useful when debugging scripts.

To save the trace to a separate file:

#!/bin/bash

exec 19>debug.log
BASH_XTRACEFD=19
PS4='+ ${BASH_SOURCE}:${LINENO}: '

set -x

echo "Starting"
ls /tmp

set +x

This sends the execution trace to debug.log instead of mixing it with ordinary terminal output.

Security warning: Don't enable command tracing around passwords, access tokens, or other secrets. Traces can expose sensitive values.

5. A practical logging template for future scripts

You can reuse this template in most of your Bash programs.

#!/bin/bash

LOGFILE="application.log"

log() {
    printf '[%s] [%s] %s\n' \
        "$(date '+%F %T')" "$1" "$2" >> "$LOGFILE"
}

log INFO "Application started"

if [[ -f "input.txt" ]]; then
    log INFO "Input file found"
else
    log ERROR "Input file not found"
    exit 1
fi

log INFO "Processing completed"

Example logfile:

[2026-10-27 08:30:00] [INFO] Application started
[2026-10-27 08:30:00] [INFO] Input file found
[2026-10-27 08:30:01] [INFO] Processing completed

Section C — Array Manipulation

Bash arrays are useful for small datasets, collections of filenames, lists of arguments, and command-line utilities.

Create an indexed array like this:

numbers=(10 20 30 40 50)

Useful operations:

Operation	Syntax
Access an element	${numbers[0]}
Display all elements	${numbers[@]}
Display array indices	${!numbers[@]}
Get the number of elements	${#numbers[@]}
Append an element	numbers+=(60)
Change an element	numbers[1]=25
Remove an element	unset 'numbers[2]'

Remember that Bash arrays are indexed from zero, and removing an element does not automatically renumber the remaining indices.

Section E — Matrices Using Bash Arrays

Bash does not provide native two-dimensional arrays in the same way as C or Python. You can represent matrices using indexed arrays, associative arrays, or a one-dimensional array with calculated indices.

For learning purposes, a one-dimensional array is a straightforward option.

For a matrix with rows rows and cols columns, map element (i, j) to:

index=$((i * cols + j))

Then access the element using:

value=${matrix[index]}

PART 3 — Three Complete Bash Programs to Study

Let's finish with three actual programs, so you can see how the concepts fit together.

Program 1: Grade calculator with logging

This program reads marks for five subjects, calculates the average, assigns a grade, and appends the result to a logfile.

#!/bin/bash

LOGFILE="grades.log"

read -r -p "Enter student name: " name

marks=()
total=0

for ((i = 1; i <= 5; i++)); do
    while true; do
        read -r -p "Enter marks for subject $i: " mark

        if [[ "$mark" =~ ^[0-9]+$ ]] && (( mark <= 100 )); then
            marks+=("$mark")
            total=$((total + mark))
            break
        else
            echo "Invalid marks. Enter an integer between 0 and 100."
        fi
    done
done

average=$((total / 5))

if (( average >= 90 )); then
    grade="O"
elif (( average >= 80 )); then
    grade="A+"
elif (( average >= 70 )); then
    grade="A"
elif (( average >= 60 )); then
    grade="B+"
elif (( average >= 50 )); then
    grade="B"
else
    grade="F"
fi

echo
echo "Student: $name"
echo "Total: $total"
echo "Average (integer): $average"
echo "Grade: $grade"

printf '[%s] Name=%s Total=%d Average=%d Grade=%s\n' \
    "$(date '+%F %T')" "$name" "$total" "$average" "$grade" \
    >> "$LOGFILE"

echo "Result appended to $LOGFILE"

Concepts used: Arrays, loops, input validation, arithmetic, conditional statements, logging, and formatted output.

The average is an integer because Bash arithmetic is integer-based. If you want decimal averages, you can use awk.

Program 2: File analyser and report generator

This program reads a text file, counts its lines, words, and characters, and writes a report.

#!/bin/bash

read -r -p "Enter input filename: " input

if [[ ! -f "$input" ]]; then
    echo "Error: File does not exist."
    exit 1
fi

read -r lines words chars < <(wc -l -w -m < "$input")

report="report.txt"

{
    echo "File Analysis Report"
    echo "--------------------"
    echo "Filename: $input"
    echo "Lines: $lines"
    echo "Words: $words"
    echo "Characters: $chars"
    echo "Generated: $(date '+%F %T')"
} > "$report"

echo "Report generated: $report"

Notice this line:

read -r lines words chars < <(wc -l -w -m < "$input")

It uses process substitution (<(...)) to provide the output of wc as input to read.

The report uses > because this program creates a fresh report each time. If you wanted to maintain a history of reports in the same file, you would use >> instead.

Program 3: Find large files and log them

This program searches a directory for files larger than a specified size and appends the results to a logfile.

#!/bin/bash

read -r -p "Enter directory: " directory
read -r -p "Minimum size in MB: " size

if [[ ! -d "$directory" ]]; then
    echo "Error: Invalid directory."
    exit 1
fi

if [[ ! "$size" =~ ^[0-9]+$ ]] || (( size < 1 )); then
    echo "Error: Size must be a positive integer."
    exit 1
fi

LOGFILE="large_files.log"

echo "[$(date '+%F %T')] Searching $directory for files larger than ${size}MB" \
    >> "$LOGFILE"

find "$directory" -type f -size +"${size}"M -print |
while IFS= read -r file; do
    filesize=$(du -h "$file" | awk '{print $1}')

    printf '[%s] %s | Size: %s\n' \
        "$(date '+%F %T')" "$file" "$filesize" >> "$LOGFILE"

    printf '%s | %s\n' "$file" "$filesize"
done

echo "Results appended to $LOGFILE"

Concepts used: Input validation, directory checks, find, pipes, loops, awk, file redirection, and logging.

One improvement for production scripts would be to handle unusual filenames robustly using find -print0 and a NUL-delimited loop. The version above is suitable for ordinary filenames but can mishandle filenames containing newline characters.

PART 4 — How I'd Practise These

Rather than attempting all 70 exercises at once, I'd divide them into four stages.

Stage	Exercises	Goal
1. Fundamentals	1–15	Conditions, loops, arithmetic, and case
2. Data structures	16–40	Arrays, strings, and matrices
3. File automation	41–60	Input validation, records, file processing, and logging
4. Advanced automation	61–70	Monitoring, integrity checks, error handling, and integrated utilities

One small recommendation: write each script in a separate file and test it with several inputs, including invalid input, empty files, missing files, and unexpected values.

For example:

mkdir -p bash-practice
cd bash-practice

touch grades.sh arrays.sh matrix.sh file_analyser.sh log_monitor.sh

chmod +x *.sh

Then execute a script using:

./grades.sh

For debugging, use:

bash -x grades.sh

And to check Bash syntax without executing the script:

bash -n grades.sh
